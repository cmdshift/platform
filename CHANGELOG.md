- **`prometheus_query`/`loki_query`: shared port-forward lifecycle + WAL-replay tolerance** (cmdshift/platform#77). The per-call forward (new kubectl + random port per invocation, 20×0.5s ready cap) churned listeners under rapid loops and hard-failed during WAL replay — both observed live in the #57 repro session. Now each tool starts one forward per service and REUSES it via a lock file (`${TMPDIR:-/tmp}/<tool>.<service>.forward`, `<pid> <port>`); each call validates PID-alive + cmdline-is-port-forward (defeats PID recycling) + HTTP answering, and evicts/replaces a stale or wedged forward in the same call (~30s worst case for a frozen listener — the liveness probe waits out curl's 2s max-time per poll). The ready check is two-budget: establish ~10s (fail fast when kubectl dies), then ready ~2m where HTTP 503 from the ready endpoint = server not ready (WAL replay/ingester replay) → wait it out, `… not ready after 2m — likely WAL replay` exit-1 with the forward left recorded so the retry rides the same one. `--stop` is the hygiene valve (the old EXIT-trap guarantee "kills what it started" becomes "no orphaned forwards — everything is lock-recorded and evictable"; acceptance amended on the issue). Ports moved off `jot` (BSD-only; its fallback pinned ONE fixed port per script on Linux — a loop-collision source on the new host) to `$RANDOM` windows: prometheus 20000-20999, loki 21000-21999. Exit codes (0/1/2) and stdout shapes byte-identical — `cpu_audit` and `tetragon_probe` consume them untouched. Out of scope, assessed: `alloy_components` (one-shot diagnostic) and `tetragon_probe`'s gRPC forward (pod-pinned, per-probe, self-cleaning). **Collateral fix in `tetragon_probe`**: the agent-pod selection (`awk … {print $1; exit}` under `set -euo pipefail`) raced kubectl's flush — awk's early exit closed the pipe and a 141 (SIGPIPE) from the command substitution killed the script at line 88 before the probe started; fixed by letting awk print all matches and `head -1` (head exits when IT has enough, awk's write then EPIPEs harmlessly inside the pipeline instead of failing the assignment). Validation: 10-call loops ×2 tools with zero failures and stable lock PIDs; three forwards coexisting (prometheus/thanos/loki, disjoint windows); wedge (SIGSTOP'd kubectl → 33s bounded eviction → fresh forward, rc 0), recycled-PID stale lock, and 503-replay mock (124s → correct message, rc 1, lock retained) — mocks in /tmp/opencode, not committed; `cpu_audit` + `tetragon_probe` end-to-end (probe still verifies enforcement: exit 137, NENFORCE +1). Live WAL-replay reproduction attempt: the pod restart converged too fast to catch the window (t+10s answers 0s — small WAL); the 503 mock carries the classification evidence, live-replay noted as untested-against-real-WAL. The lifecycle is duplicated in both scripts by design — keep them in lockstep (README pointer).
