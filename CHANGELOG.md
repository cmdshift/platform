# Changelog

Narrative log of the platform's evolution, newest first. Dated learnings, incident stories, and decision history live here; durable procedures live in `runbooks/local/`, timeless per-group decisions in `manifests/local/*/README.md`, and landmines in `.agents/skills/`. Issue/PR references use the `cmdshift/platform#N` form.

## 2026-09-08

- **RabbitMQ operators out, NATS + NACK in** (cmdshift/platform#52). Removal was the clean kind: the vendored renders carried their 13 CRDs under the datastores kustomization's `prune: true`, so deleting the files pruned deployments, webhook configs, certificates, and CRDs in one reconcile — no manual sweep (contrast the kubeblocks abort). Replacement: both charts from one `nats` HelmRepository (`nats-io/k8s`) — nats 2.14.6 (single replica, JetStream fileStore 2Gi, promExporter + PodMonitor, nats-box disabled) and nack 0.35.0 (HelmRelease `dependsOn` nats, `nats://nats.datastores.svc:4222`, CRDs in the chart's `crds/` dir). Landmines: every NATS-stack image ships **no USER directive** — `runAsNonRoot` fails the kubelet check without an explicit `runAsUser` (65534, house precedent; local-path PVCs are 0777 so the fileStore is writable); nats-box's bootstrap is not idempotent across container restarts (`[ -s context ]` misses symlinks → `ln` aborts the `-ec` script → CrashLoop) — disabled instead of carrying a command override for a debug-only pod; the chart's PodMonitor was invisible to prometheus until `podMonitorSelectorNilUsesHelmValues: false` joined its ServiceMonitor sibling in `kube-prometheus-stack-values.yaml` (scrape verified via `up{namespace="datastores"}`). The values-only-CM trap cost three rounds this session (nats ×2, kube-prometheus-stack ×1): **reconcile the owning group kustomization (`flux_wait`) before annotating the HelmRelease** — an HR reconcile that races the CM apply renders stale values, the rollout times out, and remediation rolls back to the old release.

- **Tetragon stage-2 flip 2: exec deny-list, straight to enforce** (cmdshift/platform#28). Skipped the issue's monitor-stream gate by user call: static evidence substitutes — every container in flux-system/policies/secrets runs its image entrypoint directly, no CronJobs, and the bootstrap "hooks" are helm.sh/hook annotations on the Bucket/Kustomization objects, not Jobs, so nothing legit execs shells at steady state or rebuild. Three policies (`exec-deny-list-{flux-system,policies,secrets}`), Sigkill via `security_bprm_check`, Prefix on shells/interpreters/net-tools. Landmines that cost debugging rounds: **`type: file` on `security_bprm_check` is a silent no-op** — schema-valid (cr_validate passes), the agent logs only a load-time validation warning ("struct linux_binprm * does not match spec type (file)") and nothing ever enforces; `type: linux_binprm` is the working type. **The 1.7.1 CRD has no `Kube` namespace matcher** — scoping is per-policy `podSelector` over pod labels (flux pods carry only `app=<controller>`; kyverno/external-secrets match their release instance label), `matchWorkloads` with the namespace expression exists upstream but not in this CRD. **Container-init execs escape pod-scoped enforcement** (verified: the probe's shell entrypoint survives every pod start; post-init kubectl execs die) — image threats are trivy/kyverno's surface. Symlink semantics: matching uses the requested path, so busybox `/bin/sh` → `/bin/busybox` still matches `/bin/sh`. Verified per policy: labeled busybox probe `kubectl exec` of `/bin/sh` → exit 137; per-node NENFORCE summed to exactly the 4 probe kills. The post-verify restart wave (kyverno exit 0/Completed, flux exit 1, kube-scheduler liveness timeouts, operator BackOffs across five namespaces) was the 09-07 etcd health-flap pattern — shared-VM load wave from the reconcile cascades, exonerated by no-137 + NENFORCE==probe-count; the exoneration ritual is now in `security/README.md`. `kubectl exec … sh` debug shells in the three namespaces are killed by design (documented; diagnostics go through the observability stack or a temporary monitor flip). Flip 3 (sensitive-host-paths override) queued behind the 1-day watches on flips 1+2; the end-state roadmap (cluster-wide runtime enforcement and its gates) captured in cmdshift/platform#60.
- **flux_wait: dependency-waiting is no longer failure** (hit live during the flip). Flux reports `dependency '…' is not ready` and `revision is not up to date` as Ready=False, so every full-tree artifact bump fast-failed mid-cascade instead of riding it out; the fast-fail now classifies by message pattern (waiting states stay pending, real errors still exit 1 immediately). Synced: `tools/bin/README.md`, platform-workflow skill.
- **Sync-container inotify drop wedged the pipeline again** (4th+ occurrence): three new manifests silently never reached the bucket until `docker restart sync-cloud-test` forced a full re-mirror. Follow-up to replace inotify with a polling re-mirror loop filed as cmdshift/platform#55.
- **Documentation restructure — decision log split by audience**: the old `manifests/local/notes.md` (387 lines of mixed dated narrative + timeless decisions) was dissolved — dated narrative/audits/incidents → this CHANGELOG, per-group decisions → 12 new `manifests/local/<group>/README.md` files, cross-cutting conventions + the hardening-deviations baseline → `manifests/local/README.md`, incident post-mortems → [runbooks/local/incidents.md](runbooks/local/incidents.md). notes.md is now a pointer stub. Skills and AGENTS.md were date-stripped (issue/PR refs are the provenance), and a second pass cross-referenced `tools/bin/` helpers everywhere hand-rolled equivalents were being recommended (`flux_wait -c` for kustomization status, `helm_wait -c` per-release, `rustfs` wrapper over raw `docker exec … rc`, `pod_status` for restart checks, `helm_verify` over hand-extracted values renders, audit tools by name in the sizing guidance) — the point of the tools is to stop regenerating the same plumbing per session. Hygiene rules added to AGENTS.md: dated learnings append to the CHANGELOG, group decisions update the matching README, and issue/PR refs are always fully qualified (`cmdshift/platform#N`).
- **Tetragon stage-2 flip 1: kernel-modules enforcement** (cmdshift/platform#28, PR cmdshift/platform#51). Burn-in audit first (the issue's gate): no leak — agent memory is a warmup ramp to ~430Mi then a GC sawtooth (380–540Mi, returns to baseline); per-node P99 477–524Mi over 5h → request 512Mi→640Mi, limit 768Mi→960Mi (`security/tetragon-values.yaml`). Stream review (~6h, two rebuilds): kernel-modules 327 events, all benign auto-load probes (`net-pf-*` socket-family probing by Go runtimes), zero real module loads; privileges-raise 0 (the `podSelector` fix holds); sensitive-host-paths 0 exported; bpf-activity all cilium/tetragon (sink-filtered). The flip: `policy-mode: enforce` with Override(EACCES) on `security_kernel_module_request` + Sigkill on `do_init_module`/`security_kernel_read_file(READING_MODULE)`, pod-scoped, `Pid NotIn host_ns`. Verified on all 5 nodes plus a live NENFORCE=24 probe (fresh busybox pod probing a missing module — the kernel then dedups repeated `request_module`, so steady-state event rate is genuinely low). Landmines that cost debugging rounds: `policy-mode` values are `enforce`/`monitor` (docs-adjacent `enforcement`/`monitor_only` fail agent-side with a load_error on every node); `spec.options` is a list of `{name, value}`, not a map; policies without `podSelector` don't reach the export sink while `enable-policy-filter: true` (working hypothesis, overnight watch-item); Talos denies `CAP_SYS_MODULE` to containers at runc create so the Sigkill path is armed but unreachable from pods. Flip-2/3 gates (exec deny-list, sensitive-host-paths override) are recorded in the issue — one flip at a time with a 1-day watch each.
- **Datastores group lands: cnpg, rabbitmq ×2, valkey** (cmdshift/platform#49, PR cmdshift/platform#50). Four operators, four install channels: cloudnative-pg via chart with `crds.create: false` (rendered 1.27MB > the 1MB release-secret cap; the 11 CRDs install via a `cnpg-crds` child Kustomization built from upstream `config/crd` at a pinned tag), rabbitmq cluster-operator + messaging-topology-operator as vendored renders (upstream kustomize overlays use `../` refs flux can't build; versioned images are ghcr-only without the `v` prefix), and valkey-operator as a clean chart. ## 2026-09-07

Six traps hit live and recorded in [runbooks/local/namespace-migration.md](runbooks/local/namespace-migration.md): the wave-ordering CNP deadlock, PolicyException CEL propagation lag, the cross-namespace port deadlock, helm-controller terminal-state replay, the old kyverno HR finalizer wedge, and kustomize patches being unable to change `metadata.namespace`.

Motivated by schema-less charts silently ignoring values-key typos; `helm_verify` renders the exact file flux ships.
- **thanos-operator upgraded for the upstream status-condition fix** (cmdshift/platform#22, PR cmdshift/platform#38): thanos-community/thanos-operator#636 (commit `831accd4`) replaced the sticky `ReconcileSuccess`/`ReconcileFailed` pair with a single recoverable `Ready` condition. - **Deployment dashboard + JSON logging** (cmdshift/platform#39, PR cmdshift/platform#44): first in-repo Grafana dashboard (`monitoring-config/platform-deployment.*`) with deployment→pod→logs drilldown; authored against kube-state-metrics v2 where `kube_pod_spec_volumes_persistentvolumeclaims_info` has no underscores and `kube_replicaset_owner` has no `deployment` label. PromQL landmines captured in `monitoring/README.md`: chained vector joins silently return empty, `label_replace` label args must be quoted, multi-join `sum by` must keep the join key, and Grafana `label_values()` variable queries are selector-only. Alloy side: k8s properties (`namespace`/`pod`/`container`/`node`) promoted to stream labels via `discovery.relabel` (cardinality unchanged — 1:1 with `instance`), making `{namespace="monitoring"}` selectors and the `HighErrorRate` alert work for the first time; `stage.pack` removed because `loki.source.kubernetes` emits no packable labels and it double-encoded every line as `{"_entry":...}`; every producer with a log-format knob flipped to JSON (the sweep table lives in `logging/README.md`; cilium/cert-manager/local-path/weed have no knob — the pipeline normalizes them). Landmines: River comments are `//` not `#` (crashlooped the pods), and ConfigMap content edits didn't reach pod volume mounts for 5+ min until a `rollout restart`.
- **Seaweed all-volumes-read-only incident**: loki flushed nothing for 4h+ (`S3: PutObject ... 500`) — the volume server's 7 slots filled in ~12h, volumes hitting `volumeSizeLimitMB: 1024` go read-only, and with no free slot every write path 500s at once; the volume server was also CPU-throttled at 93% of CFS periods during vacuum. Open follow-up: no alert fired during the 4h of failed flushes — a loki-flush/seaweed-volume-exhaustion ruler alert is a gap. Post-mortem: [runbooks/local/incidents.md](runbooks/local/incidents.md).

- **Bootstrap hang root-caused and fixed** (cmdshift/platform#4, PR cmdshift/platform#46): the `talos_machine_bootstrap` "indefinite hang" was Docker Desktop's host port publisher going stale after rapid container churn — host listener ACCEPTs but black-holes the forward into the VM, and the talos provider silently retried the TLS handshake for its 10m default timeout. ## 2026-09-06

- **Kubescape adopted and removed same day** (PRs cmdshift/platform#24, cmdshift/platform#26): the operator's node-agents died at startup on every node — the Docker Desktop linuxkit 7.0.12 kernel ships `CONFIG_FANOTIFY_ACCESS_PERMISSIONS=n`, so fanotify permission events fail `EINVAL` (tried and reverted). The scan's purpose survived: the NSA baseline went 80 → 92.3 with zero failing controls, the hardening settings it drove stay as `# NSA hardening:` comments, and the **accepted-deviations ledger** (thanos CRD limits, seaweed master roFS, velero chart securityContext, loki/alloy SA tokens, …) moved to `manifests/local/README.md`. Strategy decision: kubescape-style platform scanning is replaced by **single-purpose hardening tools** (runtime: tetragon; static: trivy-operator; episodic: kube-bench). The kernel intel generalizes — check the linuxkit kernel config (`/proc/config.gz`) before adopting any tool needing fanotify permission events or LSM hooks; see `security/README.md`.
- **Tetragon adopted, observability-first** (PR cmdshift/platform#29): chart 1.7.1 from the existing `cilium` HelmRepository; four monitor-only TracingPolicies (kernel-modules, privileges-raise, bpf-activity, sensitive-host-paths); tetra CLI access via node-loopback gRPC + `kubectl port-forward`. Kernel verification closed the kubescape question — linuxkit 7.0.12 has `CONFIG_DEBUG_INFO_BTF=y`, kprobes, fmodret (eBPF tools work; fanotify-permission-event tools don't) — but also that `CONFIG_BPF_LSM=y` is *not* proof of LSM-hook support: the vmlinux BTF lacks `bpf_lsm_*` symbols, so `lsmhooks:` policies fail to load (kprobes on the same symbols work; `free_module` is inlined in this kernel build). Landmines: CRs whose CRDs a release's operator creates must live in a group that dependsOn that release, never the reverse; `wait: true` on conditionless CRs stalls the full timeout per attempt; `cr_validate` was born from this session's dry-run failures.
- **Trivy-operator adopted** (PR cmdshift/platform#32): static vulnerability/config/RBAC scanning to complement tetragon's runtime view. The scan-job admission trap: trivy scan jobs are kyverno-checked, the operator hardcodes an empty pod-level securityContext, and without `trivyOperator.scanJobPodTemplate*` values scanning **silently never runs** — plus `runAsUser: 65534` is load-bearing because the image declares `USER root`. Built-in trivy-server (StatefulSet + PVC caching trivy-db) so scan jobs stop downloading ~75MB of DB each; `scanJobTTL: 10m`; CIS/infra-assessment specs dropped (node-collector hostPath mounts can't exist on Talos) with NSA/PSS specs vendored as CRs.
- **Request audit: memory requests rebalanced** (new `request_audit` tool): requests had lagged steady-state usage while limits were repeatedly evidence-bumped. Tier-1 bumps (steady usage ≥60% of request): seaweedfs-operator 50→120, cilium-agent 256→288, source-controller 160→224, kyverno admission 200→208, velero node-agent 80→88, seaweedfs-admin 96→104, thanos-operator 64→80, cert-manager 80→96 (+limit 144). The kyverno bump re-landmined as predicted (hostNetwork rollout deadlock — `kyverno_unblock` fixed it in one call). Tier-2 recheck at 24h covered the rest. kube-apiserver runs ~1.8Gi against a 512Mi request (talos-managed, not fixable in this tree).
- **Prometheus delivery + scrape fixes**: the entire kubernetes-mixin rule set had been evaluated but never delivered — the chart's alertmanager component is disabled (Alertmanager is CR-managed) and the Prometheus CR's `spec.alerting` was null; fixed via `alertingEndpoints` → `alertmanager-operated.monitoring:9093`. And `serviceMonitorSelectorNilUsesHelmValues: false` un-scaped kyverno/thanos/velero ServiceMonitors the chart default's release-label requirement had left unscraped (chart gotchas: `serviceMonitorSelector: {}` directly doesn't render; cilium needs `prometheus.serviceMonitor.trustCRDsExist: true` because helm-controller renders without API discovery).
- **kube-proxy metrics fixed at the source** (cmdshift/platform#23): kube-proxy 1.33+ binds metrics to `127.0.0.1:10249` so Prometheus targets sat at connection refused; fixed in `cluster/local/nodes/templates/cluster.tftpl.yaml` (`metrics-bind-address: 0.0.0.0:10249`) and applied by the rebuild — no live patches. The monitoring CNP's 10249 egress rule is load-bearing.
- **PVC volume stats arrived**: `kubelet_volume_stats_*` only exists for volumes kubelet can stat, and hostPath PVs are skipped — the 2026-09-05 local-PV conversion (all 8 PVs `local`) made the series appear. Cloud note: hostPath-style provisioning silently empties these series.
- **Loki retention + seaweed delete-path proof**: `retention_period: 30d`, compactor retention enabled with seaweed as the delete-request store (s3.json identities grant explicit `Delete:` on the loki/thanos buckets); Loki 3.x timing knobs shortened locally for observable feedback (`delete_request_cancel_period` defaults to a whopping 24h) — cloud keeps upstream defaults. Open observable: an actual S3 `DeleteObject` round-trip (`loki_compactor_deleted_lines_total` appearing).
- **StorageClasses: `allowVolumeExpansion: false` on purpose** — local-path has no expansion code (verified in the v0.0.37 source; only create/delete ActionTypes), so a `true` value would wedge any PVC resize forever. Resize path locally = recreate the PVC (velero FSB restore for data). Cloud CSI expands natively.
- **Flux polling loosened for interactive determinism**: bucket 1m→5m, kustomizations 10m→1h (bootstrap twins keep 1m/10m until flux-config adopts). Propagation is event-driven (5s retryInterval), so latency is unaffected; the win is background reconciles stop interleaving with interactive edits — the 1m bucket poll could publish a half-mirrored artifact mid-edit. Drift-heal at 1h remains the everything-in-files enforcement.
- Loki zero-ingestion (#27) fix attempt shipped this day (PR cmdshift/platform#30); the root cause — an earlier edit that **overwrote** the `alloy.configMap` values block, making the chart silently install its example config — was fully resolved the next day (see 2026-09-07).
