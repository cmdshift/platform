# flux

The flux v2 controllers themselves + `flux-config/` (the `Bucket/main` source and root `Kustomization/local` — the CR lives at `manifests/clusters/local/flux-config/local.kustomization.yaml`, `path: ./manifests/clusters/local`, mirrored by the bootstrap twin in `cluster/local/bootstrap/main.tf`).

## Source of truth chain

Local file → sync container (full `rc mirror --overwrite --remove` re-mirror every 5s) → `flux` bucket on rustfs → `Bucket/main` → root `Kustomization/local` → children in dependency order. Pipeline mechanics and wedge recovery: [runbooks/local/pipeline-wedged.md](../../../runbooks/local/pipeline-wedged.md).

## flux-config owns the pipeline's own objects

The root `local` Kustomization and `main` Bucket are managed by the `flux-config` kustomization (`force: true` adopts them from the terraform bootstrap's helm-hook objects on every fresh install). They're duplicated in `cluster/local/bootstrap` `extraObjects` — close enough, not identical (the bootstrap twin is minimal; flux-config converges both on first reconcile). **A bad edit to either wedges the pipeline silently** (everything keeps running, nothing applies) — fix forward with `kubectl -n flux-system edit kustomization local` / `edit bucket main`, **never delete them** (the root has `deletionPolicy: Orphan`, but its absence stops all reconciliation).

**`local.kustomization.yaml` is the one deliberately unregistered file in the tree** — the root Kustomization CR cannot be a resource of the kustomization that flux reconciles (flux can't own its own root pointer), so it sits next to `flux-config/kustomization.yaml` unregistered while the terraform bootstrap applies its HCL twin (`ignore_changes = all`; flux-config's `force: true` adopts it). The `kustomization_audit` guard skips exactly that file by name — every other unregistered yaml in a kustomize dir is a "silently never deployed" orphan, not an exception.

## Flux API traps

- **Kustomizations**: `wait: true` **ignores** `spec.healthChecks` — gate custom resources on real operator status with `spec.healthCheckExprs` (CEL; in use on the `*-config` kustomizations); copy battle-tested expressions from https://fluxcd.io/flux/cheatsheets/cel-healthchecks/ (ClusterIssuer, ClusterSecretStore, etc. — only the apiVersion **group** is matched, `kind` optional for group-wide entries). Two exprs landmines: **empty conditions pass vacuously** (`.all` over `[]` is true — a CR the operator hasn't reconciled yet reads Ready, so gate on the operator's single Ready condition knowing that), and **never wait on conditionless CRs** (TracingPolicy et al. have no status — the health check polls the full `timeout` per attempt, failing with `no matches for kind` while the CRD demonstrably exists; find the real loaded-signal elsewhere, e.g. `tetra tracingpolicy list` + an alert). A single transient failure mid-rollout is not a wedge — re-poll before diagnosing (a terminating old pod counts as unavailable via the CR status).
- **Verify new API fields against the on-cluster CRD schema before pushing** (`kubectl get crd <crd> -o jsonpath='{.spec.versions[0].schema.openAPIV3Schema.properties.spec.properties.<field>}'`) — undeclared fields fail the root dry-run ("field not declared in schema") and wedge the whole dependency chain (`healthyWhen` did exactly this). When unsure of a flux/CRD API shape, fetch the upstream docs or CRD (webfetch) instead of guessing. Kustomize dry-run caveat: every tree dir now carries an explicit `kustomization.yaml` (registration-explicit everywhere since cmdshift/platform#183), so `kubectl kustomize` builds in every dir — but it still isn't a completeness check for what flux will apply.
- **The flux2 chart's `securityContext` values replace, not merge** — the chart's securityContext template swaps its whole defaults block when ANY `securityContext` value is set, so the full container context must be spelled out: providing only `runAsGroup` silently dropped `allowPrivilegeEscalation: false`, `capabilities.drop: ALL`, and `readOnlyRootFilesystem: true` from every controller (hit live on the NSA gid hardening; the pod was still admission-legal, just unhardened — caught by review, not admission). Applies to every controller section of `flux-values.yaml` (`helmController`, `kustomizeController`, `sourceController`, `notificationController` — see the repeated "values replace the chart's sc defaults" notes).
- **Kustomization `timeout` is the annotate-preemption window** (cmdshift/platform#171): the controller serializes reconciles per object, so an in-flight health-check wait blocks a `requestedAt`-triggered reconcile for the whole `spec.timeout`. Tree-wide `timeout: 3m` (2m/5m preserved where deliberately set) — a long timeout doesn't make reconciles more reliable, it just hides a stuck one from the next fix.
- **Values CMs react instantly — if they carry the watch label** (helm-controller): every values ConfigMap in this tree carries `reconcile.fluxcd.io/watch: Enabled` and helm-controller reacts to its edit within seconds of the CM applying — no annotate, no suspend. The deployed helm-controller (from flux2 chart 2.20.0, `flux.helm-release.yaml` in this dir) has had the config watcher since v1.4.0 (fluxcd/helm-controller#1258), GA with Flux v2.7 (fluxcd/flux2#5446); the default `--watch-configs-label-selector` is exactly `reconcile.fluxcd.io/watch=Enabled`, so the label alone opts in — no controller args. **The landmine**: a NEW values configMapGenerator missing the label (rule: the `writing-yaml` skill) silently regresses to interval-only pickup — for such a legacy/unlabeled CM the recovery ladder is the `helmrelease-stuck` skill's valuesFrom-staleness section. Diagnosis: `flux_triage` (attempted/applied revision lag).
- **"Controller ≥ vX" is NOT a CVE fix boundary — check the image BUILD date, not the release date** (cmdshift/platform#263): kustomize-controller v1.9.6 shipped 2026-10-01 but was built on alpine 3.23 *before* the 2026-10-22 brotli bump — its image carries vulnerable brotli-libs 1.2.0-r0 (CVE-2026-111497); chart 2.19.1 ships v1.9.5 (unfixed) too, and no chart version ships v1.9.6. Chart **2.20.0** is the lowest fixed chart (kustomize-controller v1.10.1, brotli-libs 1.2.1-r0, verified by reading `/lib/apk/db/installed` out of the published image — flux SBOMs are Go-only and don't list alpine packages). Same class of trap as trivy 0.76.1 (built pre-Alpine-3.24.3) — for CVE fixes that ride base-image rebuilds, the fix boundary is the base bump, not the version tag.

## Polling intervals (deliberately loose)

Bucket `main` 5m, root + child kustomizations 1h drift-heal (`retryInterval: 5s` everywhere). Propagation is **event-driven** — artifact change + `dependsOn` requeue at 5s — so the loosened intervals cost nothing in latency; what they buy is background reconciles not interleaving with interactive edits (the old 1m bucket poll could publish a half-mirrored artifact mid-edit and the whole chain would apply it). The bootstrap twins run 1m/10m until flux-config adopts and converges them — keeps fresh rebuilds fast. **Do not suspend kustomizations** — a suspended tree reconciles nothing on rebuild, breaking the one-shot requirement. Cloud keeps tighter 10m/1m (multiple operators make frequent drift-heal worthwhile).

## Flux alerting (cmdshift/platform#182)

The notification Provider + Alert objects (`flux-system.provider.yaml` / `flux-system.alert.yaml`) are **deleted** — transient error events lost to persistent not-ready metrics. Flux health alerting rode scraped `gotk_resource_info` metrics via the `o2-alerts-library` fluxcd pack — **that metric is GONE from the v2.7-era controllers (source v1.9.2 / helm v1.6.2): upstream moved CR-state metrics to kube-state-metrics custom-resource-state config (`flux_resource_info`, fluxcd/flux2-monitoring-example#35), and nothing seed-fakes a missing controller-native metric.** The three flux detectors are live again (openobserve-sync Job, cmdshift/platform#206) — adapted to `increase(controller_runtime_reconcile_total{result="error"}[15m]) > 0` with per-kind `controller` label regexes (`helmrelease` / `kustomization` / `gitrepository|helmrepository|bucket|ocirepository`), same not-ready semantics, verified against the live O2 series. `flux_image_issue` stays parked (image automation runs `create: false` — its stream can never exist). The scrape job (`flux-controllers`, pod-role SD on the `app` label, named port `http-prom`) is what the detectors read — mechanics and landmines: [bases/observability/README.md](../observability/README.md).

## Sizing

Burst-heavy delivery components (source/helm-controllers) carry 1000m CPU / 512Mi-1Gi — starving them wedges the whole pipeline (evidence-bumped; see the resource-sizing skill). Per-controller evidence (migrated from `clusters/local/flux/flux-values.yaml`): helm-controller sawtooth 69-248Mi overnight — request = P99×1.2, 512Mi limit holds (peak 48%); kustomize-controller steady 178Mi (first in line for eviction under node pressure) — 224Mi = P99×1.2, 512Mi limit holds (delivery components wedge the whole pipeline when starved); notification-controller steady 260Mi — 320Mi = P99×1.2.

### flux-values notes (`clusters/local/flux/flux-values.yaml`)

- `securityContext` pod-level non-root on controllers: from the hardening baseline (chart sets container level only). Every controller section spells out the FULL container context because of the replace-not-merge trap above — the values file deliberately carries no shortcut comments for it now.
- The single-writer rule for the `flux` bucket (only the sync container writes it; `rc rm --recursive` silently no-ops) lives in the `rustfs-ops` skill.
