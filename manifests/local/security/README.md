# security

Tetragon (runtime, eBPF) + trivy-operator (static posture) + `security-config/` (TracingPolicies, vendored compliance specs, PolicyException). Episodic kube-bench runs are temp scaffolding, not committed manifests. All three replaced platform-wide posture scanning (kubescape: adopted and removed same day — too heavy for what it delivered; its NSA hardening settings survive in the manifests).

## Kernel intel (linuxkit 7.0.12, Docker Desktop VM)

Check the kernel before adopting any tool in this class — the cost of not doing it is a startup-dead DaemonSet on every node:

- **fanotify permission events are unavailable** (`CONFIG_FANOTIFY_ACCESS_PERMISSIONS=n`, `docker run alpine zcat /proc/config.gz`) — killed the kubescape node-agent's container watcher at startup on every node; the init is unconditional, so no partial-enable workaround. This killed kubescape (cmdshift/platform#24).
- **eBPF tools are proven viable**: `CONFIG_DEBUG_INFO_BTF=y` (+ `/sys/kernel/btf/vmlinux`), `KPROBES`/`KPROBE_EVENTS`, `FTRACE_SYSCALLS`, `TRACEPOINTS` — verify via `talosctl read /proc/config.gz | zcat | grep BTF` (no extra container needed).
- **`CONFIG_BPF_LSM=y` is not proof of LSM-hook support**: the vmlinux BTF lacks `bpf_lsm_*` hook symbols, so `lsmhooks:` policies fail to load ("lsm hook security_file_open not found in BTF"). Ritual: `talosctl read /proc/kallsyms | grep -wE "[Tt] (<symbols>)"` **before** writing the policy, then `cr_validate` before `sync_wait`. Plain kprobes on the same symbols work, and `fmodret: true` is supported, so Override stays available via kprobes. Inlined symbols (`free_module`) don't attach; local `t` symbols (`do_init_module`) do.

## Tetragon

- Release `tetragon.helm-release.yaml` (chart 1.7.1, same `cilium` HelmRepository as cilium — no new source); PSS `privileged` on the `security` namespace; PolicyException in `policies-config/` (agent runs privileged with host paths `/proc`, `/sys/fs/bpf`, `/sys/kernel/tracing` — the Talos ≥1.12 tracefs requirement); CNP in `networking-config/`. TracingPolicy CRDs are operator-managed (`crds.installMethod: operator`) — tiny release, no hook jobs, no 1MB-secret risk.
- **Stage-1 observe policies** (`security-config/*.tracing-policy.yaml`, all monitor_only): kernel-modules, privileges-raise, bpf-activity, sensitive-host-paths. Alert rules in `monitoring-config/thanos-rules.yaml` (`tetragon-alerts` group).
- **Policies MUST carry `podSelector: {matchLabels: {}}`**: per-hook `matchNamespaces Pid NotIn host_ns` did NOT exclude host processes live (runc's container-setup setuid calls kept firing) — the working "k8s pods only" filter is the policy-level podSelector (sensors then show a non-zero FILTERID). Worse: policies **without** a podSelector don't reach the export sink at all while `enable-policy-filter: true` (tetra gRPC sees everything regardless).
- **Stage-2 flips are manifest edits** (`spec.options`), never `tetra tp set-mode` — flux is the source of truth. Flip 1 (kernel-modules → enforce, Override(EACCES) on `security_kernel_module_request` + Sigkill on `do_init_module`/`security_kernel_read_file(READING_MODULE)`) shipped with burn-in evidence (cmdshift/platform#28): Override-on-request exists because every Go runtime's first socket() probes missing modules — a strict Sigkill would murder arbitrary controllers; Talos denies `CAP_SYS_MODULE` to containers, so the Sigkill path is armed but unreachable from pods. Flip-2/3 gates (exec deny-list via `security_bprm_check`; sensitive-host-paths override) are tracked in the issue — one at a time, 1-day watch each.
- Option-value trap: `policy-mode` is `enforce`/`monitor` (upstream `TpStringToMode`) — `enforcement`/`monitor_only` fail agent-side with a load_error on every node while flux apply "succeeds". `spec.options` is a **list of `{name, value}`**, not a map — the on-cluster CRD schema settles both.
- Agent sizing is burn-in-audited (request 640Mi / limit 960Mi; memory is a warmup ramp then GC sawtooth, data cache capacity-bounded — evidence at the value in `tetragon-values.yaml`).
- **tetra access**: gRPC binds node loopback (`tetragon.grpc.address: localhost:54321`) — `kubectl -n security port-forward ds/tetragon 54321:54321` then `tetra --server-address localhost:54321 ...`; nothing exposed on the node IP. Subcommand is `getevents` (no `events`, no `--policy` filter in 1.7 — grep the compact output). See the observability skill for the exporter-labels gotcha.

## trivy-operator

- Chart `aqua/trivy-operator` — the docs site the URL points at is v0.3.0-era; **read the chart's values.yaml instead** (schema-less chart: `helm template` doesn't reject key typos). Values live in `trivy-values.yaml` via configMapGenerator → `valuesFrom`; the release spec itself stays minimal.
- **Values-key traps (silently ignored)**: operator pod resources are top-level `resources`, not `operator.resources`; `scanJobsConcurrentLimit`/`scanJobTTL` are `operator.` keys, not `trivyOperator.`. Caught only by inspecting the render.
- **Scan-job admission trap** (operator-generated pods are kyverno-checked): the operator hardcodes an empty pod-level securityContext — without `trivyOperator.scanJobPodTemplate*` values every scan job is denied and scanning **silently never runs**. `runAsUser: 65534` is load-bearing (image declares `USER root`; bare `runAsNonRoot` fails the kubelet image-USER check). Scan-job sizing must cover the **worst image in the fleet** (pods mirror the target's container list) — bumped to 512Mi/768Mi from OOM evidence, verified by forced rescan.
- **Built-in trivy-server** (`operator.builtInTrivyServer`): StatefulSet + local-path PVC caching trivy-db/java-db so scan jobs hit `trivy-service:4954` instead of downloading ~75MB of DB each (the values comment saying 4975 is stale).
- `scanJobTTL: 10m` TTL-deletes completed jobs. **Failed scans never requeue**: an OOMKilled/failed scan job is TTL-deleted, the 120h report cache blocks rescan, and the controller resync does not recreate failed scans — force a rescan by deleting any one **sibling** VulnerabilityReport of that workload.
- CIS compliance spec + infra assessment are **off on purpose** (node-collector jobs mount standard-Linux paths — Talos is neither, hostPath mounts would be admission-denied); NSA + PSS baseline/restricted specs are **vendored as CRs in `security-config/`** — re-vendor deliberately on chart bumps.
- `ignoreUnfixed: false` — full picture on purpose; the `TrivyCriticalImageVulnerabilities` alert (warning severity, Critical-only, platform namespaces) is informational and hardened against rescan-gap flaps with `max_over_time(...[30m])` (cmdshift/platform#36).
- **All pull paths run through the caching registry** (`mirror.gcr.io` chart default isn't in the angos upstream map): tool images → `image.registry`/`trivy.image.registry: docker.io`; scan-job targets → `trivy.registry.mirror` string-rewrite (`ghcr.io/x` → `registry.cloud.test/ghcr/x`; `index.docker.io` normalized form — both prefixes); server DB → `dbRegistry: registry.cloud.test` + `dbRepository: docker/aquasec/trivy-db`. The cache is plain HTTP via haproxy — `trivy.insecureRegistries` and `operator.builtInServerRegistryInsecure` are load-bearing.
- **Cold-start race on fresh rebuild** (expected, self-healing except the status-less ClusterSbomReport): [runbooks/local/cluster-rebuild.md](../../runbooks/local/cluster-rebuild.md).
- valuesFrom gotcha: changing the values ConfigMap does not re-trigger the HelmRelease — `flux reconcile helmrelease trivy-operator -n security --with-source` after values-only edits (cmdshift/platform#31 pattern).

## kube-bench (episodic, not committed)

One-shot CIS benchmark as temp scaffolding (namespace `kube-bench-scan` with privileged PSS + scoped PolicyException + temp CNP, delete-ns cleanup) — spec lives in `cluster/local/.tmp/kube-bench-scan/`, run via `tools/bin/bench`. Pin the benchmark explicitly (kube-bench releases lag k8s; cluster is 1.36.4 → cis-1.12 is the closest released set).

**Talos intel for any future hostPath-mounted tool** (each cost a debugging round):

- **The kubelet's rootfs is curated** — `/var/lib/etcd` is invisible to hostPath mounts even though machined sees it (`hostPath type check failed: is not a directory`). Node checks can only cover paths kubelet itself needs (`/etc/kubernetes`, `/var/lib/kubelet`).
- **Control-plane static pod manifests are served, not stored** (`staticPodURL`) — `/etc/kubernetes/manifests/` on disk is empty. Remap trick: dump apiserver/controller-manager/scheduler specs via `kubectl get pod -o yaml` into an emptyDir mounted at `/etc/kubernetes/manifests`; etcd stays uncovered (machined service, not a pod).
- **Nested mounts need a writable parent** — a hostPath File inside a ro hostPath Directory fails at runc; use emptyDir parent + ro hostPath children.
- The kube-bench image ships sh + kubectl + busybox — one container, no initContainer needed; kubectl audits use `KUBECONFIG` (mount the admin kubeconfig as a Secret; CNP needs `toFQDNs cmd.local.test :6443`).

Triage ledger from the first run (zero true-positive FAILs; the rest is benchmark-vs-Talos layout mismatch): 1.2.30 `--service-account-extend-token-expiration` unset; 1.3.7/1.4.2 scheduler + controller-manager `--bind-address=0.0.0.0`; 4.3.1 kube-proxy metrics on 0.0.0.0; 1.2.5 `--kubelet-certificate-authority` absent (Talos-managed trust path). The `--authorization-config` file form (verified `Node, RBAC`) is where cis-1.12 expects the legacy flag; perms FAILs were podspec-dump emptyDir artifacts. Cloud re-verify: the layout noise mostly disappears on real nodes — see [manifests/cloud/notes.md](../../cloud/notes.md).
