# cluster/local

Terraform/docker side of the local test cluster — network, companions, Talos node containers, bootstrap. Topology and decision records: [ARCHITECTURE.md](ARCHITECTURE.md) (which also indexes every module's README); rebuild procedure: [runbooks/local/cluster-rebuild.md](../../runbooks/local/cluster-rebuild.md). Hosts: Linux with Docker Engine, and macOS where **OrbStack is the recommended runtime** (Docker Desktop still supported) — host setup: root README.

## Terraform / Docker traps

- **The kubeconfig/talosconfig embed the cmd hostname verbatim** — `talos_cluster_kubeconfig.endpoint` is only the fetch path; the embedded server URL comes from `cluster.controlPlane.endpoint` (`https://cmd.local.test:6443`, baked into the cert SANs; `cmd` is a conf output pointing at the load LB — there is no cmd container). The outputs are the pre-cmdshift/platform#54 raw shapes (`kubeconfig = kubeconfig_raw`, `k8s_client_config` raw, `talosconfig` with a cmd-IP→hostname replace) — no loopback rewrite. The host resolves `cmd.local.test` via dnsmasq, so kubectl and the bootstrap terraform providers need nothing else. In-cluster consumers must NOT use the host loopback (pod loopback) — `tools/bin/bench` rewrites the server to `kubernetes.default.svc:443` when staging the kubeconfig Secret.
- **Published host ports can go stale after rapid container churn** (destroy → recreate of a port-publishing container within ~a minute): the host listener still ACCEPTS connections but black-holes the forward into the container — container and node stay healthy, only the host→container published path dies. Hit live on the LB's `:50000` (cmdshift/platform#4); the published API ports (6443/50000) live on the **unified load LB container** (`cloud-test` — it fronts 6443 too since cmdshift/platform#192, so a stale binding puts all four ports on it), and restarting it is NOT a node reboot (the LB just drops its connections; the ctrl nodes keep running), so recovery is `docker restart $(docker ps -q --filter name=cloud-test)`, re-apply (only bootstrap + kubeconfig remain; seconds). The bootstrap/kubeconfig resources carry 10s `timeouts` — a hang surfaces as a fast error, not a wedge. Diagnose with `curl -skf --max-time 3 https://127.0.0.1:6443/version` (hang/black-hole = dead binding; 401 = publisher alive). Full story in [runbooks/local/cluster-rebuild.md](../../runbooks/local/cluster-rebuild.md); same failure shape as the companion `cloud-test` restart note in that runbook.
- **The strict machine-config static-pod decoder takes down nodes silently** — one unknown policy field in a template (the audit policy was the incident) drops the kube-apiserver static pod with no container logs. Validate schema before it lands in a template; preview the RENDERED config when diagnosing (recipe in ARCHITECTURE.md → decision records, cmdshift/platform#90/#131).
- **Companion state is disposable except the angos cache and rustfs data volumes** — the registry's `platform-registry-data` and storage's `platform-storage-data` volumes survive destroys (see the registry and storage landmines in the rebuild runbook).
- **Bucket changes (the `buckets` list in `cluster/local/conf/outputs.tf`) recreate the storage container** — data now persists on the `platform-storage-data` volume and the entrypoint provisions idempotently, so recreates are non-destructive; removing a bucket from the list leaves its data orphaned on the volume (remove manually via the `rustfs-ops` skill).
- **Locally-built images: the `cluster/local/images/` module builds + pushes to angos** (cmdshift/platform#171). angos accepts `docker push` (undocumented; terraform `docker_registry_image` works) **only with real credentials** — the push password is generated in `registry/push.tf` (`random_password` → argon2id), the images module receives it as an input and scopes a `provider "docker" { registry_auth {...} }` block to itself (which also means the images module can't take `depends_on` from the caller — the input reference supplies the implicit ordering). Mechanics and policy: [images/README.md](images/README.md), [registry/README.md](registry/README.md).
- **The bootstrap root carries `lifecycle.prevent_destroy`** — `just bootstrap destroy` always fails by design. Bootstrap mechanics (adoption twins, hubble disabled until flux's cilium install): [bootstrap/README.md](bootstrap/README.md).
- **The load haproxy rejects any HTTP Host missing from `hosts.map`** — the `cloud_backend`'s `set-dst` no-ops on a map miss, leaving dst = haproxy itself, and the request re-enters the frontend (infinite recursion, connection flood, OOM 137 — hit live via a talos-backup virtual-host PUT, cmdshift/platform#94). The unmatched-Host `default_backend http_reject_backend` makes a map miss fail closed (403) instead; if a new `*.cloud.test` name ever 403s, add it to the `hosts` map in `cluster/local/main.tf`, don't bypass the reject. Routing mechanics: [load/README.md](load/README.md).
- **The bootstrap-twin root Kustomization path must match the manifest tree layout** — `cluster/local/bootstrap/main.tf` sets `path = "./manifests/clusters/local"`, which must equal the root Kustomization CR's `spec.path` in `manifests/clusters/local/flux-config/local.kustomization.yaml`; they move together on any restructure of the tree.

## Terraform plans that look scary but aren't

kreuzwerker/docker provider churn (arbitrary ordering and re-serialization in the provider internals) shows up as replacements/in-place updates on resources no edit touched. Verdict rule: read the diff, not the action verb — identical values both sides = churn, apply through; any meaningful value differing = stop. Procedure: the `terraform-churn` skill.
